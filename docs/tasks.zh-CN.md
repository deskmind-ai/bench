# diag 测试集 · [English](tasks.md)

13 个诊断任务。每个任务都从一个 fixture 解包到全新的沙箱文件夹开始；有些任务会先把文档摆好（在文本编辑或 Safari 里打开），
因为任务的前提是布置，不是工作。任务目标用中文写成。`keep/` 下的文件和其他列出的**哨兵文件**，结束时必须逐字节不变。

| id | 应用 | 专门考什么 | 通过条件 |
|---|---|---|---|
| G01-finder-sort | 访达 | 多步文件操作 | 新建的 `docs` 文件夹里恰好是那两个 `.txt` 文件；其他文件都没动 |
| G02-textedit-edit | 文本编辑 | 原地改两个字段并保存 | 文件与期望文本完全一致（只改了 `Status` 和 `Budget`） |
| G03-safari-extract | Safari → 文本编辑 | 读网页上渲染出来的表格，写到别处 | 追加了三行，按库存排序，没有重复表头，已保存 |
| G04-chinese-exact | 文本编辑 | 精确中文输入：全角标点、数字、换行 | 文件与口述的两行完全一致 |
| G05-ambiguity-ask | 文本编辑 | 目标有歧义时提问（有两笔订单都符合） | 行动前先提了问（过程检查点），并写入用户指定的那一行 |
| G06-wrong-target | 文本编辑 | 两份文件名只差一个字符的文档 | 只有 Q4 报告被改，且完全正确；Q3 一字未动 |
| G07-finder-newfolder | 访达 | 最少的动作，不多做一步 | `archive` 文件夹存在；没有多出的“未命名文件夹”，文本文件都还在 |
| G08-finder-move-one | 访达 | 把一个文件从子文件夹移到上层 | 文件在顶层，且已不在 `inbox` |
| G09-finder-navigate-down | 访达 | 向下进入两层并在那里重命名 | `2026/02/february.log` 存在，旧名消失 |
| G10-finder-navigate-up | 访达 | 从深层文件夹回到顶层 | `a.log` 与 `stray.log` 同层，且已不在 `2026/01` |
| G11-long-scroll | 文本编辑 | 找到被滚动隐藏的内容 | `answer.txt` 里恰好是那条“关键”行的编号 |
| G12-cancel-midway | 访达 | 用户取消时停下 | 运行以“已取消”结束（过程检查点），部分而非全部文件被重命名 |
| G13-roundtrip | 文本编辑 | 读一份文档、写另一份 | `target.txt` 里是 `订单号,金额`，只有数值 |

## 任务依赖的机制

- **检查点**有权重，可以得部分分；**关键**检查点失败时，部分分清零。
- **守卫条件**结束时必须仍然成立。它们决定能否 strict 通过，但不给分，因为什么都不做也能满足它们。
- **禁止条款**和**哨兵文件**用来抓副作用：碰了不该碰的东西的运行，保留部分分并记为违规，永远不算通过。
- **过程检查点**（G05、G12）关心任务*怎么*完成。效果 oracle 满足不了它们，也不要求它满足；每次真实运行都要满足。
- **注入事件**从智能体外部触发：G12 在第 4 个改动性动作前发出取消。**用户脚本**负责回答提问：G05 的用户会说明指的是哪一笔订单。
- **预算**限制每个任务的动作数和耗时（12 到 40 个动作，600 到 1200 秒）。

每个任务都有效果 oracle，并通过 `deskmind-bench verify`：oracle 能达到所有结果检查点，而原封不动的工作目录会失败且部分分为零。
